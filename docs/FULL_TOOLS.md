# Полные MCP-инструменты работы с данными 1С

В ветке `feature/full-object-tools` добавлен контейнер `mcp_ИнструментДанные1С`. Он дополняет исходный MCP-сервер высокоуровневыми операциями над объектами базы и документами.

## Инструменты

| Tool | Назначение |
|---|---|
| `onec_find_objects` | Поиск справочников/документов по точным фильтрам |
| `onec_read_object` | Чтение объекта и табличных частей |
| `onec_write_object` | Создание/изменение справочника или документа |
| `onec_delete_mark` | Штатная пометка удаления |
| `onec_post_document` | Штатное проведение |
| `onec_unpost_document` | Отмена проведения |
| `onec_create_on_basis` | Создать документ через штатное `Заполнить(Основание)` |
| `onec_fill_on_basis` | Перезаполнить существующий документ по основанию |
| `onec_execute_query` | Read-only запрос языка запросов 1С |
| `onec_get_document_movements` | Фактические движения документа по всем заявленным регистрам |
| `onec_read_register` | Чтение физической таблицы регистра |
| `onec_batch` | Атомарный набор операций в одной транзакции |

## Главное правило проведенных документов

`onec_write_object` намеренно отказывает, если существующий документ уже проведен и запрошен `writeMode=save`. Это не позволяет агенту изменить тело проведенного документа, не пересоздав движения.

Для изменения проведенного документа используйте атомарную последовательность:

```json
{
  "operations": [
    {"tool": "onec_unpost_document", "args": {"name": "ЗаказПоставщику", "uuid": "..."}},
    {"tool": "onec_write_object", "args": {"metaType": "Documents", "name": "ЗаказПоставщику", "uuid": "...", "fields": {"Комментарий": "исправлено"}}},
    {"tool": "onec_post_document", "args": {"name": "ЗаказПоставщику", "uuid": "...", "postingMode": "nonoperational"}}
  ]
}
```

Если любой шаг завершится исключением, `onec_batch` откатывает всю транзакцию.

## Создание на основании

Для конфигураций УТ/ERP ключевой инструмент — `onec_create_on_basis`. Он не пытается воспроизводить реквизиты документа вручную:

1. создает документ через менеджер документа;
2. вызывает штатное `Документ.Заполнить(Основание)`;
3. применяет только явно переданные override-поля/табличные части;
4. записывает или проводит документ.

Пример:

```json
{
  "targetDocument": "ПриобретениеТоваровУслуг",
  "basisMetaType": "Documents",
  "basisName": "ЗаказПоставщику",
  "basisUuid": "00000000-0000-0000-0000-000000000000",
  "writeMode": "post",
  "postingMode": "nonoperational"
}
```

Это принципиально отличается от ручной сборки `ПриобретениеТоваровУслуг`: зависимые аналитики, распоряжения и внутренняя бизнес-логика остаются на стороне конфигурации 1С.

## Типизированные значения

Обычные строки, числа и boolean передаются напрямую. Специальные значения передаются дескрипторами.

### Ссылка

```json
{
  "$type": "ref",
  "metaType": "Catalogs",
  "name": "Контрагенты",
  "uuid": "11111111-2222-3333-4444-555555555555"
}
```

Для документов `metaType` равен `Documents`.

### Перечисление

```json
{
  "$type": "enum",
  "name": "ХозяйственныеОперации",
  "value": "ЗакупкаУПоставщика"
}
```

### Дата

```json
{"$type": "date", "value": "2026-10-13T15:30:00"}
```

### UUID

```json
{"$type": "uuid", "value": "11111111-2222-3333-4444-555555555555"}
```

Ответы используют те же дескрипторы, поэтому возвращенный `ref` можно без преобразований передать следующему tool.

## Запросы

`onec_execute_query` принимает только текст, который после обрезки пробелов начинается с `ВЫБРАТЬ`. Инструмент предназначен для чтения, discovery и сложных выборок/виртуальных таблиц. Количество возвращаемых строк ограничивается `maxRows` (не более 5000).

Пример параметра запроса со ссылкой:

```json
{
  "query": "ВЫБРАТЬ ПЕРВЫЕ 20 Т.Ссылка, Т.Наименование ИЗ Справочник.Номенклатура КАК Т ГДЕ Т.ВидНоменклатуры = &Вид",
  "parameters": {
    "Вид": {"$type": "ref", "metaType": "Catalogs", "name": "ВидыНоменклатуры", "uuid": "..."}
  }
}
```

## Движения документа

`onec_get_document_movements` берет список регистров непосредственно из `Метаданные.Документы.<Имя>.Движения` и читает записи с фильтром `Регистратор = документ`. Поэтому `Проведен=true` больше не является единственным критерием успеха: агент может проверить реальные движения.

## Права

Добавлена роль `mcp_ИнструментДанные1С`. Она дает право `Use` только контейнеру инструментов. Права чтения/изменения справочников, документов и регистров основной конфигурации по-прежнему определяются штатными ролями пользователя 1С, под которым выполняется MCP-запрос.

## Ограничения намеренно оставлены

- CRUD реализован для `Catalogs` и `Documents`; остальные типы доступны через read-only query/register tools.
- произвольный вызов методов общих модулей/менеджеров не предоставляется: такой tool превратился бы в удаленное выполнение произвольного BSL-кода;
- `onec_execute_query` — только read-only;
- запись проведенного документа без распроведения блокируется.

Эти ограничения являются защитными границами, а не отсутствующей функциональностью.
